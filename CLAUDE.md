# Working rules for this project

The person I'm working with is learning to code and is acting as product
manager; I act as the engineer. These rules govern how I work on this repo.

1. **Explain every change in plain English.** Before or alongside any code
   change, say what the change does and why, without assuming prior coding
   knowledge. Avoid unexplained jargon.
2. **Small changes, one feature at a time.** Follow the step-by-step order
   in `PLAN.md`. Don't bundle multiple features into one change. Don't build
   ahead of the current step.
3. **Don't add libraries, frameworks, or tools without asking first.** This
   includes npm packages, CSS frameworks, build tools, CDNs — anything not
   already in the project. Explain what it would add and why before asking.
4. **After every step, give exact instructions to open and test the app.**
   State precisely what file to open, what to click, and what the person
   should see if it worked. Don't say "test it" without saying how.
5. **Save a working version with git after each completed, tested step.**
   One commit per feature/step, with a plain-English commit message.
6. Keep the stack as simple as possible for the stated goal (see `PLAN.md`
   for the current stack and why). Don't introduce complexity (servers,
   databases, accounts, build steps) unless the product need changes and
   it's discussed first.
